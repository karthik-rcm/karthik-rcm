    1.2 What the model actually sees
    
    
    
        
    TOOLS = [{    "type": "function",    "name": "get_claim_status",    "description": "Look up the current status of one claim by claim ID.",    "parameters": {        "type": "object",        "properties": {"claim_id": {"type": "string"}},        "required": ["claim_id"],    },}, ...]   # check_auth_on_file looks the same
    
        
    The model never sees your Python. It sees a name, a description and the input shape. It picks tools from that alone, so the description is really a prompt.
    
    
    

    
    1.3 Professor's notes
    
    
    
      
    🎓 RCM bridge: this is a 276/277 claim status inquiry.The model writes the request, like a 276. Your code sends it and gets the 277 response back. The model never touches the clearinghouse. It only reads what you hand it.
    
      
    🎓 Your code is the HIPAA boundary.The model asks for CLM-1001. Your function decides whether this user may see it, logs the access, and returns only the fields needed. Access control and audit logs live in your code, never in the prompt.
    
      
    🎓 Every lap is a billed model call.Scenario 2 makes 3 model calls, not 1, and each one carries the growing history. MAX_TURNS caps both the bill and a model stuck calling tools forever.
    
      
    🎓 Every framework is this loop with extras.LangChain, the Claude Agent SDK and Foundry Agents all run this same loop for you. Once you can write it raw, you can debug any of them.
    
    
    

    
    1.4 Check yourself
    
    
    
      
    1. Who actually runs get_claim_status, the model or your code?
        
    Your code. The model only writes a function_call item, which is just JSON text. That's why permissions, logging and protected health information (PHI) rules belong in your code.
    
      
    2. How does the loop know it's finished?
        
    The model's response has no function_call items, only text. MAX_TURNS is the backstop if that never happens.
    
      
    3. In scenario 3, why does every result carry a call_id?
        
    The model asked two questions at once. call_id tells it which result answers which question. If you mix them up, it reads CLM-1003's status as CLM-1001's.
    
      
    4. In scenario 2, who decided to check for a prior auth?
        
    The model, after it read the CO-197 denial. You never wrote "if CO-197, check auth." That decision is what makes this an agent and not a script.
